EAG Ingenieros S.A.S. · MVP · Versión 3.0 · 2026-09-18

Plan de acción e historias de usuario del MVP

Plataforma de apoyo al análisis de oportunidades de SECOP II para EAG Ingenieros S.A.S. Una aplicación web que consulta oportunidades reales, reúne y procesa sus documentos, extrae los requisitos con IA validando cada cita contra el texto fuente, los compara con el perfil de la empresa y produce un borrador que una persona revisa y aprueba antes del informe.

El proyecto no depende de entregables de EAG. Se construye con datos públicos reales de SECOP II, base de datos propia y perfil empresarial cargable desde la plataforma. Cada pregunta sin responder tiene una respuesta provisional del equipo, marcada como tal.

01 · Plan de acción

12 semanas para un MVP defendible

Plan de implementación con las decisiones adoptadas en la auditoría técnica del 10 de septiembre de 2026: resuelve inconsistencias del plan original y los riesgos de costo, cobertura y dependencias. Sujeto a validación de EAG.

En una frase: Construir una aplicación web productiva (React + FastAPI + LangGraph) que consulte oportunidades de SECOP II, reúna y procese documentos, compare requisitos con el perfil de la empresa y produzca un borrador de evaluación revisado por humanos antes de generar el informe.
CríticaA1 · Modelado de roles2 roles base (Administrador, Analista) + permiso fino «approve/send» asignable. El Aprobador/Gerencia se implementa como permiso configurable, no como rol separado. Alinea HU-33 a HU-37 y resuelve la contradicción con el plan original.
CríticaA2 · Pliegos en ZIPSe admiten con extracción en sandbox y controles explícitos: ratio anti zip-bomb, profundidad máxima 5, tamaño por miembro, escaneo antivirus por miembro, sin symlinks ni path traversal. Preserva la cobertura real de SECOP frente a HU-12.
CríticaA3 · Arquitectura de autorizaciónFastAPI como capa de autoridad (conexión service_role; RLS para Storage y bucket privado). Permisos resueltos en servidor, nunca en claims del navegador (HU-04). Evita confiar en RLS para datos de negocio.
CríticaA4 · Aprobación por snapshotAl aprobar se congela una versión del análisis (expediente + perfil + decisiones). Cambios posteriores crean una versión nueva; no se invalida retroactivamente (HU-34 se cumple congelando, no invalidando).
CríticaA5 · Autonomía de datosEl proyecto NO espera la autorización de tratamiento de datos de EAG. El perfil empresarial se carga desde la plataforma con datos aportados por el usuario autorizado, y el piloto se ejecuta con oportunidades públicas de SECOP II. La autorización pasa de bloqueante externo a política interna documentada.

02 · Cómo leer este documento

Comportamiento necesario, no estado actual

Las historias se agrupan por capacidad y se vinculan con las issues del backlog para facilitar planificación, pruebas y revisión. Formato: narrativa «Como [persona], quiero [capacidad], para [valor]» · criterios observables · prioridad P0 (imprescindible) o P1 (configurable o aplazable) · trazabilidad con la issue.

Analista

ROL OPERATIVO

Busca oportunidades, reúne documentos, revisa requisitos, corrige resultados y prepara el borrador.

Administrador

ROL DE GESTIÓN

Gestiona acceso, configuración compartida, perfil empresarial y operación autorizada.

Aprobador / Gerencia

ROL DECISOR

Aprueba una versión del análisis y toma la decisión empresarial. Su designación exacta está pendiente.

Sistema / Equipo operador

ROL TÉCNICO

Ejecuta procesos controlados y mantiene seguridad, trazabilidad, retención y recuperación.

Reglas transversales: una recomendación no sustituye la decisión humana y el MVP no postula ofertas automáticamente. La fuente del requisito y la evidencia empresarial se conservan por separado (documento, localizador, fragmento y versión). Ausente o desconocido no equivale a cero. Los documentos y textos de licitación son contenido no confiable, nunca instrucciones para el sistema. Archivos, datos personales, secretos y documentos internos permanecen fuera de Git y de logs.
03 · Mapa del alcance

Secuencia principal

El recorrido de cada oportunidad dentro del MVP. Las capacidades operativas y de retención atraviesan todo el flujo; el piloto valida el resultado completo.

  1. SECOP II— Sincronización y detalle de oportunidades oficiales
  2. Expediente— Documentos con origen, versión y cuarentena
  3. Extracción— Texto y OCR trazables por localizador
  4. Requisitos— Extracción estructurada con IA y citas validadas
  5. Perfil EAG— Evidencias empresariales versionadas
  6. Comparación— Propuesta explicable y corregible
  7. Revisión— Estados controlados y justificación
  8. Aprobación— Solo después de revisión humana
  9. PDF— Informe aprobado y trazable
  10. Correo autorizado— Solo a destinatarios configurados

06 · Exclusiones explícitas

Lo que este MVP no hace

Límites declarados para evitar expectativas fuera de alcance.

  • Postulación automática de ofertas o decisión autónoma de participar.
  • Garantía de adjudicación, precisión no medida o reducción de tiempo presentada como resultado.
  • Fuentes distintas de SECOP II en la primera versión.
  • Registro manual de oportunidades; la carga manual se limita a documentos complementarios de una oportunidad SECOP II.
  • WhatsApp, Telegram, facturación, aplicación móvil y personalizaciones avanzadas.
  • Buckets públicos, enlaces permanentes, expedientes completos adjuntos por defecto o contenido sensible en observabilidad.
  • Uso de documentos internos con un proveedor externo sin autorización empresarial específica.
Nota final: este documento debe revisarse con EAG antes de convertir las historias en compromiso de producto. Los estados de avance, integraciones y resultados del piloto se verifican por separado en las issues y evidencias de prueba.
